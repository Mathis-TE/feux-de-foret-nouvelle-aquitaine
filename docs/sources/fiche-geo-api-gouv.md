# Fiche source — API Découpage administratif (geo.api.gouv.fr)

**Auteur :** Amine ASBANE · **Documentation consultée le 18/11/2026 :** geo.api.gouv.fr/decoupage-administratif (rubriques Communes et Utiliser l'API), page data.gouv.fr « API Découpage Administratif - (API Geo) », guide data.gouv.fr « Utiliser l'API Découpage administratif », page api.gouv.fr/api/geoapi.
**Fichier ouvert :** `communes.json`, réponse de `https://geo.api.gouv.fr/communes?codeRegion=75&fields=nom,code,centre,surface,population` (région Nouvelle-Aquitaine, téléchargée le 18/11/2026), ainsi que la réponse pour la Gironde. Le fichier `data/communes_na.csv` du groupe n'a pas été ouvert.

| Rubrique | Valeur |
|---|---|
| Propriétaire et système | Producteur : Direction interministérielle du numérique (DINUM), contact geo@data.gouv.fr ; partenaires : Etalab, INSEE, OpenStreetMap. Système : API Géo, volet « Découpage administratif », base `https://geo.api.gouv.fr`. *(La fiche du groupe indiquait Etalab / INSEE : le producteur affiché sur data.gouv.fr est la DINUM.)* |
| Mode d'accès et format | API REST publique, accès ouvert, sans clé. Réponse JSON ou GeoJSON (`format=geojson`). Coordonnées WGS-84. Limite : 50 appels par seconde et par adresse IP. Point d'accès utilisé : `/departements/{code}/communes` avec le paramètre `fields` pour choisir les attributs. |
| Grain (une ligne = ?) | Une commune : un objet JSON par commune avec 5 champs, `nom`, `code`, `centre` (GeoJSON Point `[longitude, latitude]`), `surface` et `population`. Vérifié sur les 4 293 objets : aucun ne manque de champ, aucune valeur `population` ou `surface` vide, 4 293 codes distincts (pas de doublon). Exemple : Abzac, code `16001`, centre `[0.7174, 46.0999]`, surface `3349.47`, population `518`. |
| Emprise géographique | Documentation : France métropolitaine, DROM et COM. Fichier ouvert : 12 départements de Nouvelle-Aquitaine, 4 293 communes (16 : 359 ; 17 : 462 ; 19 : 277 ; 23 : 255 ; 24 : 503 ; 33 : 534 ; 40 : 327 ; 47 : 319 ; 64 : 545 ; 79 : 252 ; 86 : 265 ; 87 : 195). Cela confirme le chiffre de 4 293 communes annoncé par le groupe pour `communes_na.csv`. |
| Période réellement couverte par les données | Référentiel courant, pas un historique. Vérifié dans la réponse : des codes manquent (ex. `33041`, `33091`, `33092`) et des communes nouvelles figurent (ex. Val de Virvée `33018`, Porte-de-Benauge `33008`), ce qui correspond à des fusions de communes. Un feu BDIFF portant un ancien code ne trouvera donc pas sa commune. Sources des données (dépôt `etalab/api-communes`) : Code officiel géographique de l'INSEE, découpage issu d'OpenStreetMap, codes postaux ; population légale de l'INSEE. Le dépôt source publie un millésime par année, le dernier étant 2026 (version 6.0.0) ; le millésime chargé par l'API à la date de l'appel n'est pas affiché : **non vérifiée**. |
| Date de dernière mise à jour affichée sur la fiche | **Non vérifiée** : aucune date de mise à jour n'apparaît sur les pages consultées. |
| Fréquence de mise à jour | Annuelle pour les données de base : le dépôt `datagouv/decoupage-administratif` publie un millésime par année (2026 : version 6.0.0 ; 2025 : 5.3.0 ; 2024 : 4.1.0), à partir du Code officiel géographique de l'INSEE et de la population légale de l'INSEE. Le délai exact entre la publication d'un millésime et son chargement dans l'API geo.api.gouv.fr n'est pas documenté : **non vérifiée** pour cet aspect. |
| Volumétrie | Fichier ouvert : 4 293 lignes (objets), 558 991 octets (environ 546 Ko) au format JSON. Pour la Gironde : 534 communes. Total des champs : population cumulée 6 150 451 habitants et surface cumulée 8 518 523 (unité de `surface`, voir « Clés »). |
| Clés disponibles | `code` : code INSEE de la commune sur 5 caractères, clé de jointure avec le `Code INSEE` de la BDIFF. Le département n'est **pas** un champ de la réponse quand on filtre avec `fields` : il se déduit des 2 premiers caractères du `code` (`2A` et `2B` pour la Corse). `surface` est bien renvoyée par l'API. Unité : non précisée par la documentation lue, mais la somme sur la région (8 518 523) correspond à environ 85 000 km² si l'unité est l'hectare, ce qui est cohérent avec la superficie de la Nouvelle-Aquitaine (de l'ordre de 84 000 km²) : **hectares** (déduction, non écrite dans la documentation). |
| Données personnelles | Aucune dans les données : communes, population agrégée, coordonnées de centres de communes. Aucune donnée sur des personnes dans les attributs documentés. |
| Licence | Données : Licence Ouverte (Etalab) ; code : MIT (README du dépôt `datagouv/decoupage-administratif`, consulté le 18/11/2026). La page data.gouv.fr de l'API affiche « Licence non renseignée », et le README ancien de `etalab/api-communes` mentionnait l'ODbL pour le découpage OpenStreetMap et les codes postaux ; le dépôt `decoupage-administratif` précise que les codes postaux sont désormais en Licence Ouverte. Pour le projet : citer geo.api.gouv.fr (DINUM / Etalab), l'INSEE comme source du COG et de la population, et OpenStreetMap contributors si les contours sont utilisés (ce n'est pas notre cas : nous n'utilisons que `centre`). |
